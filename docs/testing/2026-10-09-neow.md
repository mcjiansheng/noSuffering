# NoSuffering 0.1.2 涅奥继续修复记录

日期：2026-10-09；实现 0.1.2，设计 v1.6。0.1.1 的跨平台核心检查保留在[原记录](2026-10-08-compat.md)，不改写为 0.1.2 的全量验收。

## 原因和修复

用户在 xht-rog 的 Steam beta、其他 Mod 启用时，刷新第一幕涅奥奖励，领取后无法继续。实际原生 `NEventRoom.SetOptions` 在事件完成后独立生成 `IsProceed` 选项，它不在事件模型的 `CurrentOptions` 奖励列表内。NoSuffering 的旧奖励点击拦截误将该按钮判为过期奖励，因此原生打开地图的动作没有执行。问题不需要第三方 Mod 才能出现。

修复仅将原生 Proceed 交回游戏处理，刷新忙碌期间仍锁定；奖励继续核对索引和对象，丢弃旧选项点击。没有新增事件、商店或战斗奖励刷新。

0.1.2 的快照格式和玩法状态与 0.1.1 相同，只允许读取这个唯一前序版本的格式 1 记录。游戏 MVID、其他玩法 Mod 与版本、运行标识、原生保存摘要仍严格一致。指纹使用游戏 `SemanticVersion` 的原始 `v0.1.x` 格式；不转换旧文件，不放宽跨游戏版本或跨 Mod 组合检查。

## 存档与部署

用户正常退出后，先在 xht-rog 备份两份原生运行及 NoSuffering/runs；副环境操作使用副本。主环境的当前存档及原伴随记录与备份摘要保持一致。部署仅更新游戏 mods/NoSuffering，原存档不转换、不删除。备份位于远端工程忽略目录 `artifacts/neow-original-save-20261009-114932`，不包含在发行包或仓库中。

最终 Windows beta DLL SHA256 为 `9c515b19af3fbba08d2c223f0583116094c5a32181acab5c3ad0fa1031fd013c`。副环境回归 `lab-20261009T040845254557Z` 加载及单人检查通过、退出码 0，旧先古记录恢复成功；四次真实刷新后领取 BOOMING_CONCH，原生 Proceed 打开地图并启用旅行。主 Steam 桌面会话也已加载同一 DLL：0.1.2 初始化，25 个 Mod 启用 / 26 个安装，SteamInitialized=True，退出码 0；临时启动任务已删除。[存档保留证据](neow-evidence/save-preservation.txt)。主环境仅做启动检查，没有将其写成单人玩法通过。

## 保留的失败和范围

早期两次诊断因测试夹具未找到无需额外窗口的奖励而失败；调整为原生候选奖励、至多四次刷新后完成。旧存档兼容验证首次因 NoSuffering 版本字符串缺少原生 `v` 前缀而失配，所有其他配对字段均一致；修正为原生格式后真实副本读取通过。以上失败原始记录保留在 artifacts，不冒充通过。

离线 Windows 副环境存在 UndoAndRestart 的 `FeatureAnnouncement.ShowAfterMainMenuReady` 空引用；Mac headless 存在纹理和退出资源警告。没有宣称整段日志无错误，也没有将其他 Mod 的异常归因于 NoSuffering。

构建、加载、单人诊断与联机分别记录。双人、满员、断线重连按用户安排留待后续；物理鼠标/UI 缩放、付费模式和额外多步奖励未在本次重测，DESIGN T01–T22 仍未完成全量验收。
