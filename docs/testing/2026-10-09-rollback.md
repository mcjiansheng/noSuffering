## 修复记录

- 跨幕 Boss 结算 marker：原生 `MapLocation` 只有 public fields、无 `JsonInclude`，`System.Text.Json` 将它写成 `{}`，造成已结算 Boss 的磁盘读回失配；`MapCoord` 有 `JsonInclude`，坐标仍正常。增加 `CombatSettlement(Coord, ActIndex)` 可序列化类型，`TimelineData` 属性持久化并内部转换到原生类型；网络 `OperationData` 也使用同一类型。Mac beta 后续运行已确认 marker 保存和读回。
- 原生启动时序与 Revision 配对：跨进程恢复时 `SetUpSavedSingleplayer` 先设置 State，`IncrementNumReloads` 随后触发低层 `SaveRun`，此时网络初始化和 `WorldRevision` 仍未完成。仅用 `IsInProgress` 判断会提前写出错误 Revision（配对记录从 4 变成 0），而只检查 `NetService` 也不足以覆盖完整原生初始化阶段。最终写入逻辑按原生 `ShouldSave` 阶段保留或更新 Revision；`CaptureEntry` 以 `!ShouldSave` 排除初始化期。Mac stable 修复版在 `SetUpSavedSingleplayer` 后实际执行 `LoadRunSave`，确认 `LoadedRevision > 0` 并成功继续；Windows beta 结算 Boss 新进程继续也确认 Revision 配对。Mac beta 的结算 Boss 新进程继续未执行。

## 失败与测试边界

- 测试夹具问题：初始洗牌异常由未等待原生初始化造成并发；CombatRulesFtue 完成标记缺失曾挡住跨幕 GUI；一次 F05 失败来自设置探针正确持久化了关闭状态而 gameplay fixture 未重开开关。修正隔离夹具后相应探针通过，均不是产品路径缺陷。
- 产品修复：结算 marker 序列化和启动期 Revision 配对问题按上述范围已定位修复；Mac/Windows stable 与 Windows beta 已有结算 Boss 新进程继续证据。Mac beta 保留未测边界。
- Windows beta：25-mod windowed Viewport 回归 7 项全 PASS；另有 headless 原生 API gameplay 探针 10 项全 PASS，覆盖 F02/F03、F01、F04/F05、普通重开保留刷新尝试及原生磁盘续档。persistent toast 内容为“遥测授权”／“有 1 个遥测申请方待处理”，`Ritsu Entry` 会池化复用；隔离 fixture 精确匹配可 dismiss 的原始 `VisibleToast`，调用公开 `Host.Close(id, false)`，不执行授权点击回调、不授权。此 toast 为 persistent，不适用默认 6 秒时长。该构建 SHA-256 `853dc4d8…`；普通战斗新进程继续、结算 Boss 新进程继续和 Revision 配对均 PASS。
