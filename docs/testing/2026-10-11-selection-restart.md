# 0.1.8 待选牌时战斗重开

日期：2026-10-11。依据：DESIGN v1.12 / T40、T41。

## 原因与修复

xht-rog 当前日志确认加载的是 0.1.6，报错来自 `GameBridge.BoundaryAsync`：等待未完成的选牌动作，20 秒后报“请先完成当前动作或选择”。截图中的“准备”卡尚在等待弃牌；模组面板覆盖了选择区域。这是等待边界不支持合法重开状态，并非牌序生成耗时。

快照替换现在允许已让出执行权的待选牌动作进入准备阶段。房主与客户端在 Ready 前冻结手牌和选牌覆盖层输入（包括其他模组覆写处理模式的子控件），中止准备时恢复原选择。提交后、第一次转场等待前，通过原生 `CombatEnded`、手牌 `AnimOut` 及覆盖层清理取消旧动作和选择；不让旧手牌退出时返回空选择并继续旧动作。原处理模式在旧局清理后、新局加载前恢复。普通重开和刷新牌序仍遵循原尝试持久化规则。

## 实际验证方法

使用真实游戏引擎的独立副环境，在原生战斗中生成并通过动作队列打出 Prepared，等待原生弃牌选择可见且动作处于 GatheringPlayerChoice；不提交任何选牌结果，直接调用普通重开及刷新牌序重开。

检查准备阶段所有手牌子节点不能处理输入、中止后原选择恢复、提交后旧动作取消、旧手牌离开场景、新手牌处于 Play 且无选牌遮罩、牌序刷新与再次普通重开一致，以及实际磁盘保存／原生继续保留新尝试。测试会跳转到第二幕，并非完整真人对局，也非 Computer Use 验证。

本轮调试中保留了失败记录：最初测试给无目标卡 Prepared 传入角色目标，修正为 null；多模组检查发现子控件处理模式覆写，随后加入递归输入锁；正式版检查误用 beta 的完成任务断言，按实际 API 修正。正式版原生 Cancel 将动作标为 Canceled，但不完成 CompletionTask；beta 会取消该任务。产品代码不修改原生任务实现。

## 范围与限制

本轮没有双客户端待选牌重开、Steam 联机延迟竞态或完整对局实测。联机准备屏障、可靠消息顺序和输入冻结进行了源码审查，不能替代联机实测。历史完整对局与其他模组组合的结果不计为本版通过。原生 headless 引擎退出时可能输出资源释放警告，按专项断言、退出码与加载结果分别记录。

具体目标结果、最终 DLL 指纹和部署结果见本页后续表格及 evidence/0.1.8/validation.json。
