# 0.1.5 奖励回滚、死亡等待与 BaseLib 设置

日期：2026-10-11（Asia/Shanghai）。需求依据：DESIGN v1.9。机器可读结果见 [validation.json](evidence/0.1.5/validation.json)。本轮完整对局未重复执行；[0.1.4 对局](2026-10-09-cua-playthrough.md)和[广泛兼容检查](2026-10-09-expansion.md)保留其原版本标记。

## 变更

- 新的战斗胜利检查点在原生奖励生成前捕获。回滚恢复胜利、领取奖励前的资源，并使用原生奖励流程重现相同卡牌候选、升级状态、随机数与稀有度状态。已领取的金币和卡牌随回滚撤回，再次领取只计一次。没有增加战斗奖励刷新。
- 待领奖保存配对生成前快照；只领取部分奖励后退出，继续时整页回到领取前，连同已领资源一并撤回。全部领取或跳过后的存档仍保留结算后的实际资源。旧检查点没有领取前快照，继续采用其原来的结算后语义。
- 死亡后回滚不再等待已结束战斗残留的敌人回合标记或已经完成的动作；实际未完成选择仍等待。准备期间的真实进展不被旧时间线覆盖，异常释放操作状态。
- BaseLib 3.4.7 为可选适配。其 Mods 页注册 NoSuffering 的 14 项设置，使用原生复选框、滑块、下拉和快捷键按钮，与自带面板共用现有配置。没有 BaseLib 程序集引用、manifest 依赖或要求安装提示；BaseLib 的配置壳不保存第二份设置值。原 ModConfig 适配保留。

## Computer Use 设置页验证

在 Mac beta 的 BaseLib 3.4.7 + NoSuffering 隔离组合中，使用 Computer Use 真实鼠标操作：主菜单“模组配置”→“NoSuffering”，看到框架原生设置页；点击路线回滚复选框关闭，读取原有 `config.json` 确认 `SinglePlayerRules.EnableMapRollback=false`；再开启，滚动查看余下费用设置，返回主菜单并正常退出。没有额外安装要求或空白阻塞界面。页面布局和鼠标开关通过；其他控件的值变化由前述原生回调检查覆盖。

最初使用完整 25 Mod GUI 副本时，其他模组欢迎弹窗关闭后主菜单能高亮，但菜单点击未激活；没有记录为 GUI 通过。缩减到上述两模组组合后相同操作正常。完整组合的原生注册、控件回调及回滚检查通过，但这个主菜单输入现象原因尚未确定，因此不宣称完整组合的物理操作或所有第三方功能兼容。

GUI 退出后的应用状态读取曾重新唤起测试副本，导致初次恢复校验多出原生日志；关闭副本后再次恢复，最终逐文件树摘要与测试前一致。所有被暂存的第三方 Mod 均已放回。测试配置和存档均为专用 NoSufferingLab 副本，未修改主游戏存档。

## 死亡竞态：理论修复，待人工验证

xht-rog 的真实 `godot2026-10-11T00.16.51.log`（66180 bytes）记录玩家死亡、原生历史结算之后，两次在 NoSuffering `BoundaryAsync → PreparationBoundaryAsync → Execute` 报“请先完成当前动作或选择”。实际 beta 的 `ProcessPendingLoss` 结束战斗但保留敌人回合标记，与旧边界等待条件对应。

现已仅在 `IsInProgress` 的战斗等待敌人回合；动作仅在执行器仍运行或 CompletionTask 未完成时等待；运行清理或替换时给出错误并释放 Busy。地图选择器在取消时清理引用，并拒绝已替换运行的旧节点。构建及其他回滚回归通过。按用户明确要求，此竞态不尝试用 Computer Use 模拟，**人工死亡时机验证未执行，不能标记通过**。

人工验收：敌人攻击时打开路线回滚，保持地图选择直至死亡，再选择既往节点；应完成恢复，或明确结束本次操作并恢复可操作状态，不应永久停留“处理中”。仍存在未完成的原生卡牌/奖励选择时，不应强行丢弃选择任务。

## 失败记录与边界

- 首轮单人诊断将三个卡牌 key 当作一个选择 key，修正诊断取首个实际 key 后通过；未发现奖励随机数差异。
- 首轮网络诊断杀怪后漏调原生 `CheckWinCondition` 安全点，等待奖励超时；改为与原生 Win 控制台一致的结束路径后双方 13 项通过。
- Windows 远程校验首次使用默认编码读取 UTF-8 manifest 失败，明确 UTF-8 后执行。未写作首次成功。
- 头无窗口引擎退出存在已有纹理/RID 清理警告；25 Mod 还包含其他模组翻译和旧依赖告警。通过结论来自具体断言，不代表日志完全无错误。
- 25 Mod 共存不等于任意模组兼容。第三方奖励生成必须基于可序列化状态确定性执行；外部随机数、全局副作用和自定义奖励保存未被本轮覆盖。ModConfig 的广泛运行证据仍属于明确标记的 0.1.4，未改记为本版框架实测。
- 四个原始副环境存档与 Mac GUI 副本均已恢复备份并校验一致。安装仅更新 NoSuffering；游戏运行时拒绝覆盖。源码、四目标安装包、构建部署脚本与本记录一同交付。
