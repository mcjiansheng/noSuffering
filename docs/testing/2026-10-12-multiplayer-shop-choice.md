# 0.1.11 联机商店与先古选择修复

日期：2026-10-12。需求依据：DESIGN v1.14。

## 现场证据

双方运行 NoSuffering 0.1.10，beta v0.111.0。房主提供的日志与 xht-rog 日志对应同一局。商店进入及房主删除“受伤”均已完成；购买后的摘要校验报“全队状态不一致”，房主随后单独进入多人恢复加载并等待客机同步，客机仍停留在商店。恢复等待阻止了后续断开与操作释放。

“华美发束”在两端的初始选项中一致，但两端均无执行该选项的记录；个人刷新后“叶状膏药”正常执行。现场日志未记录选择请求的具体阶段与拒绝原因。

## 根因与修复

原生双进程复现顺序为：房主领取“沉重石板”并完成选牌 → 房主广播状态 → 客机领取“华美发束” → 进入未刷新的商店 → 房主删除原生奖励产生的“受伤”。修复前双方 Native、Combat、Shop、Boss 摘要完全一致，Ancient 的 Players[1].Finished 分别为 false / true。CaptureState 只在返回副本中投影真实领取状态，没有在房间结束时更新内部记录；收到房主 State 的客机存入 true，房主自身仍为 false。离开先古后旧记录再次参与商店校验，产生误报。复现证据为 artifacts/macos/public-beta/mp-20261012-204709。

首次选择还有一条可复现的会话竞态：客户端在收到房主 State 前发送空 epoch 选择请求，房主在进入请求处理前丢弃，原生按钮已经清空。修复等待已认证会话后发送，并在失败时恢复原生选项；记录消息阶段与拒绝原因。

多人提交后失败改走原生断开与回菜单，停止单端调用多人恢复加载。单人保留快照恢复。摘要保留完整比较，并增加组件指纹以区分后续问题。

Windows beta 的 25-Mod 副环境还复现了开局标识不同：游戏在各端用本机 UTC 秒数建立 StartTime，而 NoSuffering 的持久运行标识包含 StartTime。修复由认证房主提供开局时间，仅在新局首次握手时验证种子与玩家阵容后统一；既有存档标识算法保持一致。回归固定让两端相差两秒，避免依赖随机时序。

## 验证

四个目标均以真实游戏程序集构建，0 警告、0 错误；各自启动原生游戏的房主和客机进程，通过 localhost ENet 完成以下定向回归及关闭重启后的续存检查。测试为 headless 隔离副环境，使用原生按钮、奖励选牌和删牌流程；单人、Computer Use 完整对局及 Steam 跨机器联机本轮未执行。

覆盖：双方开局时间相差两秒时会话收敛；房主沉重石板领取与 State 广播；客机过期会话点击恢复选项；等待会话后领取华美发束且金币归零；未刷新商店删除受伤；个人商店刷新、客机送货员购买；新进程继续后商品与种子一致。主动注入摘要不一致后，双方在 15 秒内回到原生菜单，Busy 释放，最后一次配对原生存档和 companion 文件哈希保持一致。

Mac beta 另通过原有 13 项联机检查（双方各 13 项，mp-20261012-205733）。Windows beta 的 25 Mod 包括 BaseLib、RitsuLib、UndoAndRestart、AncientSL；本轮覆盖上述具体场景。各目标 DLL 指纹和两端结果见 [机器记录](evidence/0.1.11/validation.json)。

调查中保留了修复前商店摘要分歧、初始会话标识不一致和种子类型比较错误的失败证据。一次 Mac 正式版启动与另一 beta 测试占用同一端口，停止重跑后通过；最终表格对应独立顺序运行。现场日志保存在本地 artifacts/investigation-20261012，含玩家与机器信息，不随发行包上传。
